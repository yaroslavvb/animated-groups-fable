Why classification-of-surfaces#sym&k=*2334 Stutters Today

In standalone/classification-of-surfaces/src/sym/pattern.js, every drag or wheel frame walks up to 4,200 hyperbolic matrices on the CPU, allocates ~20 Path2D buckets per frame, and oscillates tile count whenever frame time crosses 34 ms.

Current: sym/pattern.js (per-frame CPU tile enumeration)
1. Raw wheel / dragCursor-anchored jump adds holonomy
2. 3,450 tiles in JSall.slice(0, budget) @29 fps
3. 20+ Path2D paths19 fills + 24 strokes each frame
4. 6.8–29.4 ms + pop-in180 ms timer flashes rim tiles
Target: pattern-gl.js + thin 2D overlay (O(1) CPU per frame)
1. 2-stage psuPowCenter pan + 450 ms scroll latch
2. 32-gon Klein fold1-dot Minkowski + 4 static UBOs
3. 0.75x FBO + 1x settle+ 1 outlined tile in 2D overlay
4. 0.10 ms JS · 1.6 ms GPULocked 60 Hz, zero rim pop-in
Architecture shift: upload static fundamental-domain UBOs once per orbifold change instead of rebuilding thousands of tiles every frame.

Non-conformal markers & hard cutoffs
